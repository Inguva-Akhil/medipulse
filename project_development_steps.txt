MediPulse - Step-by-Step Development Workflow

This document records the exact process we followed to build the MediPulse platform from scratch.

Phase 1: Project Setup & Dependencies
---------------------------------------------------------
1. Inspected the existing `medipulse-backend` directory to identify dependencies (Express, Mongoose).
2. Generated the frontend application using Vite with the React template (`npx create-vite`).
3. Installed required frontend dependencies: `react-router-dom`, `recharts`, `react-leaflet`, `socket.io-client`, `lucide-react`, and `axios`.
4. Installed required backend dependencies: `socket.io` for real-time web socket connections.

Phase 2: Backend Architecture & Database setup
---------------------------------------------------------
1. Defined MongoDB Schemas (Mongoose) for the core data:
   - `User.js`: Handles roles (Citizen, Hospital, Authority).
   - `Hospital.js`: Stores geo-location and live resource counts (ICU beds, ventilators, blood bank).
   - `SymptomReport.js`: Stores citizen symptom submissions for AI tracking.
   - `Alert.js`: Stores outbreak alerts generated by the system.
2. Created Express routes:
   - Auth routes (`/api/auth`) for login/register.
   - Hospital routes (`/api/hospitals`) to update and fetch resource counts.
   - Surveillance routes (`/api/surveillance/report`) to accept citizen symptom reports.
3. Implemented Mock AI Logic: In the surveillance route, logic was added so that if more than 5 "Severe" symptom reports are received, an Outbreak Alert is generated.
4. Integrated Socket.io in `server.js` to broadcast real-time events (`newAlert` and `hospitalUpdated`) whenever data changes.

Phase 3: Frontend Development & Premium UI
---------------------------------------------------------
1. Crafted a premium, custom CSS design system (`index.css`) featuring glassmorphism, glowing gradients, smooth micro-animations, and a responsive grid layout.
2. Configured React Router in `App.jsx` to navigate between the three primary portals.
3. Created Reusable Components:
   - `Navbar.jsx`: A responsive top navigation bar using Lucide-react icons.
4. Built Page Views:
   - `CitizenView.jsx`: Allows citizens to locate nearby hospitals and securely report symptoms.
   - `HospitalPortal.jsx`: Allows staff to adjust live bed counts and save them.
   - `Dashboard.jsx`: The Authority overview featuring live alerts and statistical trackers.

Phase 4: Real-Time Integration & Quality of Life (QoL) Improvements
---------------------------------------------------------
1. Wired the Frontend to Backend: Replaced placeholder frontend logic with actual `fetch` requests hitting the Express REST APIs.
2. Socket.io Subscriptions: Updated the `Dashboard.jsx` to actively listen for `hospitalUpdated` and `newAlert` socket events to update the React State instantly, creating a live data feed.
3. Implemented Database Fallback Mechanism: Updated `server.js` so that if a user doesn't have a local MongoDB installed, the backend gracefully catches the error and auto-downloads/starts `mongodb-memory-server` (an in-memory database).
4. Auto-Seeding: Added logic to inject a dummy "General City Hospital" into the database on startup so the UI is immediately testable.
5. Unified Startup Command: Initialized a root `package.json` and installed `concurrently`. Set up the `npm start` script to launch both the backend and frontend at the exact same time from a single terminal command.
