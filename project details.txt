=======================================================
MEDIPULSE TRIAGE & SURVEILLANCE SYSTEM
Project Overview & Architecture Details
=======================================================

1. INTRODUCTION
MediPulse is a full-stack, real-time medical triage and city-wide surveillance system. It is designed to act as a digital bridge between citizens, individual hospitals, and a centralized health authority to optimize emergency medical responses, manage hospital resources, and detect outbreaks early.

2. TECHNOLOGY STACK
- Frontend: React.js, React Router, Recharts (for analytics), CSS Variables for theming.
- Backend: Node.js, Express.js.
- Database: MongoDB & Mongoose (Schema-driven).
- Real-Time Communication: Socket.io (WebSockets).
- Real-World Data: Integrated with a custom CSV dataset of 213 hospitals and 2,975 doctors in Bangalore.

3. SECURITY & AUTHENTICATION (RBAC)
- JWT Authentication: The system uses robust JSON Web Tokens (JWT) for secure session management.
- Password Hashing: Uses bcrypt to securely encrypt user passwords in the database.
- Role-Based Access Control (RBAC): The frontend includes strict route guards (`ProtectedAccessRoute.jsx`) that prevent unauthorized access.
  - Citizens cannot access the Hospital or Authority boards.
  - Hospitals can only access their specific queue management portals.
  - Only Health Authority Admins can access the city-wide surveillance dashboard.

4. CORE COMPONENTS

A. The Citizen Portal
- Allows users to self-report symptoms, location (zip code), and demographic details.
- Calculates a "Severity" score (Mild, Moderate, Severe) based on the inputs.
- Automatically routes the patient to the nearest/most suitable hospital's incoming queue.

B. The Hospital Portal
- Acts as the operational hub for hospital staff.
- Dynamic Resource Tracking: Staff can monitor and update bed counts (General, ICU, Observation) and ventilators.
- Smart Triage Queue: Incoming patients are sorted automatically by severity and arrival time.
- Internal Doctor Assignment: Staff can search their roster of specialty-balanced doctors and assign them to "Moderate" and "Severe" patients instantly.
- Treatment Pipeline: Tracks patients through "Pending" -> "Treating" -> "Observation" -> "Discharged" phases. Doctor availability automatically syncs based on these phases.

C. The Health Authority Dashboard
- A "Command Center" for city-wide surveillance.
- Active Outbreak Alerts: Uses an automated background script to detect spikes in critical symptoms in specific zip codes, pushing real-time AI warnings to the dashboard.
- Report Trends: A live-updating Recharts graph showing the surge of citizen reports.
- Severe Case Management (High Priority Inbox): The Authority can directly oversee all "Severe" cases city-wide. If a hospital is overwhelmed, the Authority can step in, find an available specialist, and force-assign them to save the patient's life.

5. REAL-TIME SIMULATION & SOCKET ARCHITECTURE
- The system includes a `simulateLiveTraffic.js` backend service. It continuously runs in the background, reading from historical datasets, and firing POST requests to simulate live patients walking into hospitals.
- Socket.io instantly propagates these changes across all connected clients. If a doctor is assigned in the Hospital Portal, they instantly disappear from the Authority's dropdowns. If a new severe patient arrives, the Authority Dashboard graph spikes upward without requiring a page refresh.

6. DATA MIGRATION ENGINE
- Custom parsing scripts (`importDoctors.js`) group real-world doctors by their exact medical specialty (Cardiology, Neurology, etc.) and distribute them equitably across all registered hospitals. This ensures every hospital has a perfectly balanced multi-disciplinary roster.
